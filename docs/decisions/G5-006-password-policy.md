# G5 认证规则调整

用户于 2026-11-02 明确将密码设置规则改为 8—24 个 Unicode 码点，并取消首次登录强制改密。该要求替代需求基线 v1.4、技术基线 v2.0 及旧任务记录中对应的强制改密语义；其他身份、角色、范围和会话规则沿用原约定。

- 初始创建和主动改密使用 8—24 字符，不截断、不剥除空格；控制字符与不完整 Unicode 仍拒绝。
- 已有凭据继续可登录，登录与当前密码输入保留 1—128 字符兼容；不因规则变化重写密码。用户指定的本机临时凭据属于已有凭据。
- 登录成功即可使用已获授权；系统管理身份仍不自动获得预约、审批或维修权限。
- Principal.mustChangePassword 保留字段兼容，当前实现恒为 false；历史 PASSWORD_CHANGE_REQUIRED 错误定义保留用于旧事件兼容，新实现不再产生首登拒绝。
- 既有数据库通过新增迁移清除旧限制，递增受影响账户版本并撤销其旧会话；新账户默认无此限制。
- 主动改密入口保留；改密成功后所有旧会话失效，需重新登录。密码散列、Cookie、CSRF、限速及服务身份规则不变。

历史实现保留在来源 G5 分支；本轮范围与验收见 [迁入任务单](../tasks/G5-MIGRATE-main-framework.md)。该变更须随身份契约交付相关消费组评审，用户需求授权不替代团队集成会签。
