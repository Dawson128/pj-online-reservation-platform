# G6：跨服务认证接线决策

状态：已实现，待提交前人工验收及相关模块PR评审。依据用户已确认的认证接线目标及明确的G5修改授权。

## 选择

G5继续保存唯一的账户、会话、CSRF散列和授权事实。G6增加一个纯Java共享库 `shared/auth-client`，由预约与维修服务装配；没有新增后端部署单元。消费者每次请求通过真实HTTP调用G5，不读m2表、不缓存成功身份、不把服务凭据作为业务用户权限。

`CampusPrincipal`是G5 Principal的不可变消费投影，字段严格按G5契约解析；不是另一个角色/权限事实源。G5-I01保留原始调用方式，可选增加 `requestMethod`（默认GET）和 `csrfToken`。新调用方总是提交真实HTTP方法；G5在同一只读快照中验证会话和写请求CSRF。只读旧调用保持兼容。

消费者使用 `ApiAccessRule` 显式登记方法、路径、所属模块、动作。框架负责身份、CSRF和粗粒度动作门禁；没有登记的路径继续拒绝。细粒度对象归属、房间/院系范围、审批回避由领域owner按当前资源事实继续判断，不能因为框架发现某条同名grant就跳过对象范围检查。

## 备选与取舍

- 复制两份过滤器：后续错误/CSRF策略易漂移，采用共享库统一。
- 跨服务读取会话表：破坏schema与模块边界，采用G5公开内省接口。
- 仅转发Cookie或仅验证浏览器Origin：不能完成既有CSRF规则，采用G5会话绑定校验。
- 新增独立CSRF端点：增加一次网络往返、可能使用不同快照，采用现有内省的兼容扩展。
- 登录成功后全局放开所有API：无法保护未接入的业务路径，采用显式动作登记加默认拒绝。

## 错误与环境

无效会话401；CSRF拒绝403并带 `details.fields[].field=csrfToken`；服务凭据错误、超时、网络错误、畸形回复均在消费者返回503 AUTH_UNAVAILABLE。客户端不解析本地化错误消息、不跟随重定向、不自动重试请求，不把异常正文或会话写入日志。

连接超时2秒、总超时5秒；消费者回复采用本次请求traceId，不回显凭据。响应流超过512KiB取消，未知字段、错误版本类型或非法scope失败关闭。

同机开发Compose显式允许私网HTTP，跨主机必须HTTPS。各调用模块使用独立随机服务凭据，仅注入对应消费者和G5；旧.env只追加缺少的key，不轮换或覆盖现有数据库密码。

## 影响

G1/G4/G3/G6未来控制器接入时，需要登记动作规则并实现对象级授权；实际房间查询、资源占用与业务恢复仍由对应owner交付。认证验收探针只在测试classpath通过PropertiesLauncher加载，产品jar和镜像不含测试探针。

没有业务schema变更。回退可经新revert PR撤回消费者接线；G5旧请求格式保持可用。现阶段不声明资源业务端到端、生产部署或完整readiness已完成。
